# p2k

Доступ в интернет через корпоративный прокси с авторизацией Kerberos
для программ, которые сами Kerberos не умеют. Рассчитан на Astra Linux
(x86_64) с входом под доменной учётной записью.

p2k решает две задачи.

1. **Терминал через прокси.** Ярлык «p2k: терминал через прокси» открывает
   терминал, в котором заданы `http_proxy`, `https_proxy` и `no_proxy`.
   `curl`, `wget`, `git`, `pip`, `apt` и другие программы в нём работают
   через обычный HTTP-прокси без логина и пароля.
2. **Браузер через Xray.** Ярлык «p2k: Chromium через Xray» запускает
   отдельный Chromium, который работает через ваш сервер Xray (VLESS и т. п.),
   а Xray подключается к нему через корпоративный прокси.

```text
Задача 1:  программа ──► px 127.0.0.1:18080 ──► корпоративный прокси ──► интернет

Задача 2:  Chromium ──► Xray 127.0.0.1:21000 ──► px ──► корпоративный прокси ──► ваш сервер Xray ──► интернет
```

`px` — локальный прокси, который проходит авторизацию на корпоративном прокси
**билетом Kerberos текущего сеанса**. Пароль вводить и хранить не нужно:
билет выдаётся системой при входе в доменную учётную запись.

## Быстрый старт

p2k распространяется одним архивом `p2k-linux-x86_64-ГГГГММДД.tar.gz`.
В нём уже лежат px, Xray и Chromium. Ничего скачивать и устанавливать
не нужно, права администратора не требуются.

1. Распакуйте архив в любое место, например в домашний каталог:

   ```bash
   tar xzf p2k-linux-x86_64-*.tar.gz -C ~
   ```

   Появится каталог `~/p2k`.
2. Откройте в нём терминал и выполните:

   ```bash
   ./setup.sh
   ```

   Если система ответит `Permission denied`, запустите `bash setup.sh`.

   Скрипт восстановит права на запуск, создаст ярлыки на рабочем столе
   и в меню приложений и проверит, что всё готово.
3. Для браузера положите свою конфигурацию Xray в файл `xray-config.json`
   в каталоге проекта. Как её составить, описано
   [ниже](#конфигурация-xray).

После этого всё запускается ярлыками. Терминалу через прокси конфигурация Xray
не нужна, он работает сразу после `setup.sh`.

## Терминал через прокси

Запуск: ярлык «p2k: терминал через прокси» или команда

```bash
./p2k-terminal.sh
```

Откроется оболочка с меткой `(p2k)` в приглашении. В ней:

```bash
curl https://example.com
git clone https://github.com/...
pip install ...
sudo -E apt update        # -E сохраняет переменные прокси для sudo
```

Одну команду можно выполнить без открытия оболочки:

```bash
./p2k-terminal.sh curl -I https://example.com
```

px запускается автоматически и останавливается, когда закрыт последний
терминал или браузер p2k. Если px уже запущен, им пользуются все окна сразу.

Адреса, которые не должны идти через прокси, добавляются переменной
`P2K_NO_PROXY` (по умолчанию в обход прокси идут только `localhost`,
`127.0.0.1` и `::1`):

```bash
P2K_NO_PROXY=".ols.vniitf.ru,10.0.0.0/8" ./p2k-terminal.sh
```

## Браузер через Xray

Запуск: ярлык «p2k: Chromium через Xray» или команда

```bash
./p2k-chrome.sh
```

Скрипт запускает px, затем Xray с конфигурацией `xray-config.json`, затем
Chromium. Когда браузер закрыт, Xray и px останавливаются, если ими больше
никто не пользуется.

Особенности браузера:

- это отдельная сборка Chromium из каталога `opt/chromium`, системный браузер
  не используется и не меняется;
- **все данные браузера** (профиль, кэш, служебные файлы) хранятся в каталоге
  `data/chromium` внутри проекта. В домашнем каталоге браузер ничего
  не создаёт;
- загруженные файлы сохраняются в обычный каталог «Загрузки»;
- WebRTC не может обойти прокси;
- пароли сохраняются в профиле без системного хранилища ключей.

Аргументы передаются Chromium:

```bash
./p2k-chrome.sh --incognito https://example.com
```

## Конфигурация Xray

Файл `xray-config.json` в каталоге проекта создаёте вы сами: в нём адрес
и ключи вашего сервера. Файл не попадает в git.

Конфигурация должна выполнять три условия.

1. **Вход для браузера** — `inbound` с протоколом `http` (или `socks`),
   адрес `127.0.0.1`. Порт по умолчанию `21000`. Скрипт сам берёт порт
   и протокол из первого такого входа. Не указывайте `0.0.0.0`: тогда вашим
   подключением смогут пользоваться другие компьютеры сети.
2. **Выход к вашему серверу** — `outbound` к серверу Xray (VLESS, VMess,
   Trojan, Shadowsocks).
3. **Подключение к серверу через px** — в `streamSettings.sockopt` выхода
   к серверу укажите `"dialerProxy"` с тегом второго выхода типа `http`,
   который смотрит на `127.0.0.1:18080`. Без этого Xray будет пытаться
   подключиться к серверу напрямую, а корпоративная сеть такое соединение
   не пропустит.

Первый `outbound` в списке используется по умолчанию, поэтому выход
к серверу должен стоять первым.

Готовый шаблон для VLESS + Reality: `xray-config.example.json`.

```bash
cp xray-config.example.json xray-config.json
```

Замените в `xray-config.json` значения, написанные заглавными буквами.
Если у вас есть ссылка вида
`vless://UUID@АДРЕС:ПОРТ?security=reality&sni=...&pbk=...&sid=...&flow=...&fp=...#имя`,
поля переносятся так:

| В ссылке                 | В xray-config.json                            |
|--------------------------|-----------------------------------------------|
| часть до `@`             | `id`                                          |
| адрес после `@`          | `address`                                     |
| порт после `:`           | `port` в `vnext`                              |
| `flow`                   | `flow` (если параметра нет, удалите строку)   |
| `sni`                    | `serverName`                                  |
| `pbk`                    | `publicKey`                                   |
| `sid`                    | `shortId`                                     |
| `fp`                     | `fingerprint`                                 |
| `spx`                    | `spiderX` (значение раскодируйте: `%2F` → `/`) |
| `type`                   | `network` (`tcp`, `grpc`, `xhttp` и т. п.)    |

Если ваш клиент (v2rayN, Nekoray, Hiddify и др.) умеет экспортировать полную
конфигурацию Xray в JSON, можно взять её: оставьте выход к серверу, добавьте
к нему `sockopt.dialerProxy`, выход `corporate-proxy` и вход из шаблона.

Проверка конфигурации:

```bash
./opt/xray/xray run -test -config xray-config.json
```

`p2k-chrome.sh` выполняет эту проверку сам и показывает ошибку, если
конфигурация неверна.

## Как работает авторизация

В `px.ini` не указаны ни имя пользователя, ни пароль:

```ini
server = proxy.ols.vniitf.ru:3128
auth = NEGOTIATE
username =
kerberos = 0
```

В таком режиме px передаёт авторизацию библиотеке GSS-API, и та берёт билет
из кэша текущего сеанса: из переменной `KRB5CCNAME` или из параметра
`default_ccache_name` в `/etc/krb5.conf`.

px использует **системную** библиотеку GSS-API, ту же, что `klist` и `kinit`.
Так учитываются доработки Kerberos в Astra Linux и модули SSSD или ALD Pro
из системной конфигурации. Если системной библиотеки нет, px берёт свою
встроенную. Выбор можно задать вручную переменной `P2K_GSSAPI`.

Проверить, есть ли билет:

```bash
klist
```

Если билета нет (например, вход выполнен под локальной учётной записью или
билет истёк), получите его командой `kinit` или войдите в сеанс заново.
Скрипты p2k предупреждают об отсутствии билета.

Корпоративный прокси указывайте по полному доменному имени, а не по
IP-адресу: Kerberos запрашивает билет для службы `HTTP/<имя прокси>`.

## Состав

```text
p2k-terminal.sh           задача 1: px и терминал с переменными прокси
p2k-chrome.sh             задача 2: px, Xray и Chromium
p2k-check.sh              диагностика входа на корпоративный прокси
setup.sh                  однократная подготовка, ярлыки
px.ini                    конфигурация px
xray-config.example.json  шаблон конфигурации Xray
xray-config.json          ваша конфигурация Xray (создаёте сами, не в git)
lib/                      общие функции скриптов
opt/px/                   готовая сборка px
opt/xray/                 Xray-core
opt/chromium/             Chromium
data/                     рабочие данные: профиль браузера, журналы
VERSIONS.txt              версии программ в архиве
```

Журналы находятся в `data/logs`: `px.log`, `xray.log`, `chromium.log`
и общий `p2k.log`.

## Настройки через переменные окружения

| Переменная              | Назначение                                          |
|-------------------------|-----------------------------------------------------|
| `P2K_NO_PROXY`          | дополнительные адреса в обход прокси                |
| `P2K_TERMINAL`          | команда терминала, например `"konsole -e"`          |
| `P2K_CHROME_NO_SANDBOX` | `1` — запускать Chromium без песочницы              |
| `P2K_GSSAPI`            | библиотека Kerberos для px: `auto` (по умолчанию), `system` или `bundled` |
| `XRAY_CONFIG`           | другой путь к конфигурации Xray                     |
| `PX_CONFIG`             | другой путь к конфигурации px                       |

Порт px задаётся в `px.ini` (параметр `port`). Если меняете его, поменяйте
порт и в выходе `corporate-proxy` конфигурации Xray.

## Частые проблемы

**Сайты не открываются, px отвечает «Proxy authentication failed: single
sign-on failed».** px не смог войти на корпоративный прокси по билету
Kerberos. Запустите диагностику:

```bash
./p2k-check.sh
```

Скрипт покажет билеты сеанса и настройки Kerberos. Затем он проверит вход
с системной и со встроенной библиотекой GSS-API. Отдельно видно, прошла ли
авторизация и пустил ли корпоративный прокси на каждый сайт. По умолчанию
проверяются `ya.ru` и `example.com`, свои сайты можно перечислить:

```bash
./p2k-check.sh ya.ru github.com pypi.org
```

Если авторизация прошла, а сайт «не ответил», его не пропускает сам
корпоративный прокси. Это правило сети, а не ошибка p2k. Такие сайты
открывайте в браузере p2k через Xray.
Полный отчёт с трассировкой Kerberos сохраняется в `data/logs/check-*.txt`.
Паролей и самих билетов в нём нет, но есть имя пользователя и имена серверов.

Частые причины:

- **нет билета**: `klist` пуст, получите билет командой `kinit`;
- **«Server not found in Kerberos database»**: прокси зарегистрирован
  в домене под другим именем, укажите это имя в `server` файла `px.ini`;
- **«Clock skew too great»**: время компьютера расходится со временем домена.

**Chromium не запускается из-за песочницы (sandbox).** В системе запрещены
пользовательские пространства имён. Попросите администратора разрешить их
или запустите браузер без песочницы (это снижает защиту браузера):

```bash
P2K_CHROME_NO_SANDBOX=1 ./p2k-chrome.sh
```

**Программы не запускаются, хотя права на запуск есть.** В Astra Linux
с включённой замкнутой программной средой (ЗПС) запускаются только
подписанные исполняемые файлы. px, Xray и Chromium из комплекта не подписаны,
обратитесь к администратору.

**Ярлык терминала не открывает окно.** Укажите свой терминал явно, например
`P2K_TERMINAL="fly-term -e"`, или запускайте `./p2k-terminal.sh`
из уже открытого терминала.

**Программа в терминале p2k не использует прокси.** Некоторые программы
не читают `http_proxy`. Для них прокси задаётся в их настройках:
`127.0.0.1:18080`, без логина и пароля.

## Удаление

```bash
./setup.sh --uninstall   # удалить ярлыки
rm -rf ~/p2k             # удалить каталог проекта
```

Вне каталога проекта p2k хранит только ярлыки.

## Сборка релизного архива

Этот раздел нужен только тому, кто готовит архив для пользователей.

В git хранятся скрипты и px. Xray и Chromium слишком велики для git,
их загружает скрипт сборки:

```bash
build/make-release.sh            # загрузить недостающее и собрать архив
build/make-release.sh --update   # сначала обновить Xray и Chromium
```

Архив и файл с его контрольной суммой появятся в каталоге `dist`.
Версии можно закрепить:

```bash
XRAY_VERSION=26.3.27 CHROMIUM_REVISION=1689747 build/make-release.sh --update
```

Загрузка идёт через px, то есть через корпоративный прокси. Если `https_proxy`
уже задан, используется он, а `P2K_DIRECT=1` отключает прокси. Контрольная
сумма Xray сверяется с опубликованной авторами. Личный `xray-config.json`
и каталог `data` в архив не попадают.

Для сборки нужны `curl`, `unzip`, `tar` и `sha256sum`. На машинах
пользователей они не нужны.
