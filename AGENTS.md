# AGENTS.md

Сведения для агентов, которые работают с этим репозиторием.

## Что это

p2k — переносимый комплект для Astra Linux (x86_64). Он даёт программам
выход в интернет через корпоративный прокси с авторизацией Kerberos
и запускает отдельный Chromium через Xray.

- `app/p2k-terminal.sh` запускает px и открывает терминал с `http_proxy`
  и другими переменными, указывающими на `127.0.0.1:18080`.
- `app/p2k-chrome.sh` запускает px, Xray (`127.0.0.1:21000`) и Chromium.
  Xray подключается к своему серверу через px (`sockopt.dialerProxy`).
- px входит на корпоративный прокси билетом Kerberos текущего сеанса,
  без логина и пароля.

Пользовательская документация — `README.md`.

## Устройство

```text
setup.sh            пошаговая подготовка; в архиве лежит рядом с app/
README.md           документация пользователя; в архиве тоже в корне
app/                всё остальное, в архиве это единственный каталог
  p2k-*.sh          пользовательские скрипты
  lib/common.sh     общие функции: сервисы, px, Xray, Kerberos, терминал
  lib/check.sh      проверка входа через временный px (setup.sh, p2k-check.sh)
  lib/ui.sh         оформление вывода setup.sh
  lib/bashrc        стартовый файл оболочки терминала p2k
  px.ini            конфиг px
  opt/px/           готовая сборка px (в git)
  opt/xray/         Xray-core (не в git, загружает build/)
  opt/chromium/     Chromium (не в git, загружает build/)
  data/             рабочие данные: профиль браузера, журналы, блокировки
build/              сборка релизного архива; в архив не попадает
```

Не в git: `app/opt/xray`, `app/opt/chromium`, `app/data`,
`app/xray-config.json*` (личные ключи), ярлыки `*.desktop` в корне, `dist/`.

## Главные требования пользователя

- **Ничего не загружать на целевой машине.** px, Xray и Chromium лежат
  в архиве. Загрузка есть только в `build/`.
- **Без зависимостей.** На целевой машине доступны только bash и базовая
  система (coreutils, util-linux, grep, sed, awk, getent). Не полагаться
  на python3, curl, jq и т. п. в пользовательских скриптах. `klist`
  и средства рабочего стола (zenity, notify-send, xdg-user-dir) — только
  как необязательные, с запасным вариантом.
- **Минимум следов в системе.** Ничего не писать вне каталога p2k.
  Chromium получает подменённый `HOME` и `XDG_*` внутри `app/data/chromium`.
  Ярлыки создаются только рядом с `setup.sh`.
- **Минимум действий пользователя.** Всё, что можно, делает `setup.sh`.
- **Релизы — только по прямой просьбе** в текущем сообщении. Коммит и push
  в `main` после изменений — можно.

## Соглашения

- Скрипты на bash с `set -Eeuo pipefail`. Совместимость с bash 5.0
  (Astra 1.7). Проверка: `bash -n` и `shellcheck -x`.
- Все сообщения для пользователя на русском. Ошибки через `p2k_fail`:
  она пишет в журнал и, если терминала нет, показывает окно.
- Пути в документации и подсказках указываются от каталога p2k:
  `app/p2k-check.sh`, `app/px.ini`.
- Ссылки на серверы Xray и содержимое `xray-config.json` содержат ключи.
  Не писать их в журналы и не выводить целиком.
- Сообщения коммитов на английском.

## Как устроены сервисы

px и Xray общие для всех скриптов p2k (`p2k_service_acquire` в
`lib/common.sh`). Каждый скрипт держит разделяемую `flock`-блокировку
`app/data/run/<сервис>.users`; запуск сериализован через `<сервис>.start`.
Последний вышедший останавливает сервис, но только если сам его запускал
(есть `<сервис>.pid`). Фоновые процессы закрывают унаследованные
дескрипторы (`p2k_close_extra_fds`), иначе блокировка не освободится.

## Неочевидное

- **Kerberos.** Встроенная в px библиотека MIT krb5 не видит билеты
  в кэше `KEYRING:persistent` на Astra с SSSD. Поэтому px запускается
  с `LD_PRELOAD` системной `libgssapi_krb5.so.2` (`p2k_px_command`,
  переменная `P2K_GSSAPI=auto|system|bundled`). В `px.ini` должно быть
  `username =` пусто и `kerberos = 0`.
- **401 «single sign-on failed»** от px означает, что прокси повторно
  ответил 407. curl пробует токен заранее, поэтому ошибка GSSAPI без
  заголовка `Proxy-Authenticate` от прокси ничего не значит
  (`p2k_auth_verdict`).
- **504 от px** после отправленного токена — прокси не открыл сайт
  за `socktimeout`. Это правило корпоративной сети, а не ошибка Kerberos.
- **Xray** определяет формат конфига по расширению: временные файлы
  должны оканчиваться на `.json`. В Xray 26 удалены `header` и `seed`
  у mKCP, `p2k-xray-config.sh` такие ссылки отклоняет.
- **Ширина рамок** в `lib/ui.sh` считается по байтам UTF-8 (`ui_len`),
  чтобы не зависеть от установленной локали.
- **px собран с UPX.** `px --version` запускает сам прокси и не завершается.

## Как проверять

- Синтаксис и линтер:

  ```bash
  bash -n setup.sh app/*.sh app/lib/*.sh build/*.sh
  shellcheck -x setup.sh app/*.sh app/lib/*.sh build/*.sh
  ```

- Конфиги не трогать: переопределять `PX_CONFIG`, `XRAY_CONFIG`, `HOME`.
  Конфиг Xray проверять командой `app/opt/xray/xray run -test -config ФАЙЛ`.
- Вышестоящий прокси без Kerberos: маленький Python-сервер на свободном
  порту, отвечающий на CONNECT, и `PX_CONFIG` с `server = 127.0.0.1:ПОРТ`.
- Kerberos: изолированный стенд с `krb5kdc` и squid с
  `negotiate_kerberos_auth` на нестандартных портах, через `KRB5_CONFIG`
  и `KRB5_KDC_PROFILE`. Нужны `qualify_shortname = ""` и
  `dns_canonicalize_hostname = false`. Пакеты после проверки удалять,
  системные службы squid и KDC сразу отключать.
- Диалоги `setup.sh` проверять в псевдотерминале:
  `script -qc ./setup.sh /dev/null < ответы`.
- Не использовать `pkill -f` с шаблоном, который совпадает с собственной
  командной строкой оболочки.

## Сборка

```bash
build/make-release.sh            # докачать Xray и Chromium, собрать dist/
build/make-release.sh --update   # обновить Xray и Chromium
```

Публикация (`gh release create`) — только по просьбе пользователя.
